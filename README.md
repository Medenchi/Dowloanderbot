# Dowloanderbot

Даунлоадер для Telegram, у которого **весь интерфейс — HTML-виджеты Bot API 10.4/10.5**.
Никаких «бот пишет текстом: выбрал качество / скачиваю / готово»: состояние, прогресс,
качество, ошибки и стрелки карусели живут в `chat_data` одного виджета, а меняется только оно.

Стиль — iOS 26/27 «liquid glass» **без градиентов**: полупрозрачное стекло, `backdrop-filter`
(ровно 1 «тяжёлый» блок, лимит профиля — 2), радиусы 26px, системный шрифт, цвета из
`--tg-theme-*`, авто light/dark. Виджет 250px высотой, без скролла.

```
┌──────────────────────────────┐
│  сообщение с фото / видео     │  ← editMessageMedia (меняется по стрелкам)
├──────────────────────────────┤
│  ┌────────────────────────┐  │
│  │ TIKTOK      карусель   │  │  ← sendWidget, HTML НЕ меняется
│  │ Photo dump             │  │
│  │ ▓▓▓▓▓▓▓▓▓░░  72%      │  │  ← editMessageWidgetData, ~1 раз/с
│  │ 360p 720p 1080p Аудио  │  │
│  │   ‹      2 / 7      ›  │  │  ← widget_query: "n" / "p"
│  │ Ещё раз Отмена Источник│  │
│  └────────────────────────┘  │
└──────────────────────────────┘
```

## Файлы (условно «3 файла», как просили)

| Файл | Что |
|---|---|
| **`bot.py`** | весь Python: aiogram-хендлеры, yt-dlp/ffmpeg, карусели, состояние, SQLite, очередь, webhook/polling |
| **`widget.html`** | единственный HTML-виджет (все фазы рендерятся из `chat_data`) |
| **`requirements.txt`** | зависимости |

Дополнительно: `.env.example`, `docs/BOT_API_WIDGETS.md` (исследование API и лимиты),
`scripts/widget_budget.py` (валидатор 4 КБ), `tests/test_bot.py` (81 тест), `pytest.ini`.

## Быстрый старт

```bash
git clone https://github.com/Medenchi/Dowloanderbot.git   # если папка уже есть — git pull
cd Dowloanderbot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
# ffmpeg нужен системный; в контейнерах часто уже стоит. Если нет и ты root:
# apt-get update && apt-get install -y ffmpeg     (sudo в минимальных образах обычно отсутствует)
cp .env.example .env          # замени BOT_TOKEN на настоящий токен @BotFather
.venv/bin/python bot.py --doctor  # без токена: версии, ffmpeg/ffprobe/gallery-dl, DNS, память
.venv/bin/python bot.py --check   # бюджет виджета
.venv/bin/python bot.py
```

`.venv/bin/gallery-dl` ищется автоматически (консольный скрипт pip часто не в `PATH`),
поэтому `--doctor` больше не пишет «НЕ НАЙДЕН» при установленном пакете. `BOT_TOKEN` из
`.env.example` помечается как «НЕ ЗАДАН (пример)», чтобы не вводить в заблуждение.

В чате: `/diag` — тот же отчёт плюс `getMe`, очередь, число сессий, `maxRSS`/потоки
и свободное место. Бот молчит, пока не попросили.

`MODE=polling` по умолчанию. Для `MODE=webhook` задать `WEBHOOK_URL`, `WEBHOOK_SECRET`,
`WEBHOOK_HOST=0.0.0.0`, `WEBHOOK_PORT`; `allowed_updates` уже включает `widget_query` и
`shared_widget_query`.

Тесты: `.venv/bin/python -m pytest tests -q` (в `pytest.ini` отключён autoload pytest-плагина
aiogram — иначе на Python 3.11 он импортируется раньше compat-шима).

> **Python:** рекомендуется 3.12+. На 3.11 `aiogram>=3.33` + `pydantic` падают при импорте
> (`TypeError: unhashable type: 'FailFast'` из-за хеширования `Annotated` в `typing` 3.11).
> В `bot.py` есть минимальный compat-шим — работает и на 3.11, это проверено тестами.

## Как работает

1. `/start` → бот отправляет **два** своих сообщения: PNG-заглушку (генерируется кодом, без
   ассетов) и под ней виджет. Заглушка потом заменяется реальным медиа через `editMessageMedia` —
   поэтому «фото сверху, виджетик снизу» сохраняется всегда.
2. Пользователь присылает ссылку. Поля ввода в виджете запрещены профилем 1 (нет `<input>`),
   поэтому ссылка — это сообщение **пользователя**; от бота текстов нет.
3. Тап по кнопке виджета → `TelegramWidget.request()` (1–64 байта) → `widget_query` →
   мгновенный `answerWidgetQuery` (дедлайн 15 с) → фоновый воркер → `editMessageWidgetData`.
   Команды короткие и из allow-list: `q:360`, `q:720`, `q:1080`, `q:a`, `n`, `p`, `r`, `x`.
4. Прогресс пушится троттлингом ~1 раз/с (правка состояния считается отправленным сообщением);
   неточный/плавый процент не жжёт лимиты. `Источник` — это `openLink` прямо из виджета.
5. `file_id` кэшируются в SQLite по `(url, качество)` и по слайдам: повторное качество и
   перелистывание карусели **не перезаливают** файлы.

## Площадки

Топ-список с подписями в виджете: YouTube, TikTok, Douyin, Instagram (Reels + карусели),
X/Twitter, VK, OK, Reddit, Twitch, Pinterest, Rutube, SoundCloud, Bilibili, Facebook,
Dailymotion, Vimeo, Threads, Snapchat, Coub, Rumble, Yandex — плюс **всё, что умеет yt-dlp**
(~1800 экстракторов, best effort). Приватные/возрастные посты — через `COOKIES_FILE`.

**Фото-карусели — отдельная история** (это важное открытие при исследовании):

* `yt-dlp` **не скачивает слайды TikTok**: на photo-пост он отдаёт только звуковую дорожку.
  Поэтому бот читает hydration-JSON страницы (`__UNIVERSAL_DATA_FOR_REHYDRATION__` /
  `SIGI_STATE`) и достаёт `imagePost.images[].imageURL.urlList`, а как второй источник зовёт
  `gallery-dl -g`.
* У Instagram фото-посты вообще не имеют `formats`; разведка идёт с
  `ignore_no_formats_error=True`, картинки берутся из `thumbnails` каждого `entries`.
* Слайды качаются в 4 потока с лимитом размера, режутся до `MAX_SLIDES`, dedupe по имени файла
  (у TikTok одно фото приходит с двух CDN-зеркал), хранятся до `KEEP_FILES_MIN`.

## Размеры файлов (гибрид)

| Ситуация | Что делает |
|---|---|
| ≤ 48 МБ | `sendVideo`/`editMessageMedia` как есть, `supports_streaming` |
| > 48 МБ | `ffmpeg` считает битрейт из длительности (`ffprobe`), жмёт в H.264/AAC под 48 МБ, `-fs` как жёсткий потолок, `nice 10` |
| Не влезает / нет ffmpeg | документ ≤50 МБ, либо кнопка «Источник» (`openLink` на оригинал) |
| Оригинал > `MAX_ORIGINAL_MB` (400) | `max_filesize` у yt-dlp рубит скачку на стороне HTTP-загрузчика |

Лимиты Bot API: 50 МБ загрузка файлом, 20 МБ если Telegram тянет по URL, 10 МБ для photo.
Свой local Bot API server (до 2000 МБ) не требуется — код к нему готов, но по умолчанию
используется официальный endpoint.

## Чтобы не легло

* `asyncio.Semaphore(MAX_PARALLEL=2)` на скачку **и** перекодировку; `MAX_QUEUE=40`, дальше —
  вежливое «очередь занята» в виджете, а не бесконечные таски.
* `max_filesize`, `socket_timeout`, `retries`, таймауты `inspect/download/encode`.
* `run_job` всегда снимает счётчик очереди в `finally`; `tmp/` чистится по TTL; видео-файлы
  удаляются сразу после получения `file_id`.
* SSRF-фильтр: только http(s), без кредов/нестандартных портов, DNS-резолв с блокировкой
  private/loopback/link-local/reserved; per-user rate limit 4 ссылки / 30 с.
* yt-dlp крутится в `asyncio.to_thread`, ffmpeg — в отдельном процессе; event loop не блокируется.
* Один запрос `request()` в полёте на виджете + `busy`-флаг в JS = не ловим `RATE_LIMITED`
  (лимит Telegram: 5 запросов / 5 с на пользователя).

## Если виджет не отправляется / видео не качается

### `INPUT_MEDIA_WIDGET_NOT_ALLOWED`

Это **не ошибка кода и не HTML**. С **13 ноября 2026** Telegram закрыл `sendWidget`
обычным ботам в продакшене — даже в личном чате. Подтверждение контрибьютора Bot API
`levlam`: [tdlib/telegram-bot-api#947](https://github.com/tdlib/telegram-bot-api/issues/947).
Официальная страница до сих пор пишет «private chat: Yes», но сервер отвечает 400. Тоггла
в BotFather нет, это серверный whitelist; срока возврата нет.

Что делать:

1. **Увидеть настоящий виджет** → `TELEGRAM_TEST_SERVER=1` в `.env`. Нужен **новый аккаунт
   в тестовом окружении** (iOS: 10 тапов по Settings → Accounts → Login to another account →
   Test; Desktop: Shift+Alt + ПКМ по «Add Account» → Test Server) и **новый бот у @BotFather
   внутри него**. Токен от продакшен-бота не подойдёт. aiogram сам уйдёт на
   `https://api.telegram.org/bot<token>/test/METHOD_NAME`.
2. **В проде** → `TELEGRAM_WIDGETS=auto` (по умолчанию): бот уходит в фолбэк на
   полноценную текстовую карточку и **повторяет попытку раз в `WIDGET_RETRY_MIN` минут** —
   чат не залипает на тексте навсегда. `off` — сразу фолбэк, без лишних запросов к API.

### Фолбэк — не «полтора предложения»

Раз виджетов в проде нет, текстовая карточка сделана основным UI, а не заглушкой:

```
🎬  YouTube
━━━━━━━━━━━━━━━━━━━━━━
▶  Скачиваю · 42%
[████████░░░░░░░░░░]  42%
✓ Разбор  ▶ Скачка  · Обработка  · Отправка
──────────────────────
Название ролика · 1:23 · HD
⚙ 720 · 12.4 МБ
──────────────────────
yt-dlp 2026.11.23 · ffmpeg ✓ · normal · /diag
```

* **Прогресс-бар**, фазы с ✓/▶, качество, размер, слайд `2/7`, техническая строка.
* При ошибке — `⚠` причина, `↳` сырая деталь (`ERROR: …`, таймаут, размер), `💡` что
  делать (прокси/куки/другое качество/`/diag`). Кнопки: качество всегда, стрелки карусели,
  «Ещё раз», «Отмена», «Помощь», «Диагностика», «Источник».
* **Бот всегда отвечает внизу чата**: `/start` и каждое новое сообщение создают НОВУЮ
  карточку рядом с сообщением пользователя, а не редактируют одно далёкое сообщение из
  начала переписки. Старая карточка удаляется, её задача отменяется и помечается `retired`,
  чтобы не плодить дубли. Прогресс в рамках одной задачи обновляется редактированием.
* Качество можно выбрать заранее, до первой ссылки.
* Тех. ключи (`d`/`h`/`b`/`low`) живут только в фолбэке и не попадают в `chat_data`
  виджета — бюджет 1 КБ не тратится.
3. Лог теперь прямо говорит причину: `Telegram отказал в виджете: INPUT_MEDIA_WIDGET_NOT_ALLOWED`.

### «Видео не качаются»

Сначала `.venv/bin/python bot.py --doctor` или `/diag`. Если в логе старта **нет** строки
`WARNING ... ffmpeg не найден` — ffmpeg установлен, дело не в нём. Теперь каждое решение
пишется в лог, так что по одной строке видно, где остановилось:

| Строка в логе | Что это и что делать |
|---|---|
| `сообщение без http(s)-ссылки` | Прислали текст без `http(s)://` — нужна полная ссылка |
| `ссылка отклонена: ... причина=Приватные адреса запрещены` | DNS площадки резолвится в `0.0.0.0`/private (часто при блокировках) — поставить `HTTPS_PROXY` или поправить DNS |
| `rate limit: chat=...` | Больше `RATE_PER_30S` ссылок за 30 с — подождать или поднять лимит |
| `разведка не удалась (...) HTTP Error 403` | Площадка режет датацентр/требует логин → `COOKIES_FILE` |
| `разведка не удалась (...) Requested format is not available` | Нет подходящего формата → другое качество или `YTDLP_EXTRACTOR_ARGS` |
| `job ТАЙМАУТ за N с` | Не отвечает площадка → `INSPECT_TIMEOUT` / `DOWNLOAD_TIMEOUT`, прокси |
| `скачка не удалась (...) ffmpeg` | Без ffmpeg yt-dlp не может слить DASH-дорожки. Бот теперь просит только прогрессивные форматы; если их нет — честно пишет «Нет подходящего формата» |
| `job failed за N с: ...` | Непредвиденное — вместе с traceback |

Исправлено по ходу разбора: после merge берётся **итоговый** `info["filepath"]`, а не самый
крупный исходник (иначе уезжал кусок без звука); `webm/mkv/mov` сразу идут документом
(`sendVideo` их не ест); при >50 МБ без ffmpeg бот не падает, а даёт кнопку «Открыть источник»;
удалённую пользователем карточку бот пересоздаёт, а не молча теряет обновления.

### «Зависает после рестарта, одни и те же ссылки по кругу»

Разбирали на `https://l.likee.video/v/...`: короткий домен **не входит** в `_VALID_URL`
`LikeeIE`, yt-dlp падал в `generic`-экстрактор и уходил грузить страницу. Плюс
`asyncio.to_thread` **не убивается** `asyncio.wait_for` — поток остаётся жить, а
`drop_pending_updates=False` после рестарта возвращал те же апдейты: две одинаковые
задачи, две сети, снова «ничего не происходит» → ручной рестарт. Замкнутый круг.

Что сделано:
* `l.likee.video` / `m.likee.video` / `likee.com` нормализуются в `likee.video` — теперь
  срабатывает родной `LikeeIE`, а не generic;
* **разведка вынесена в отдельный процесс** (`sys.executable -m yt_dlp -J ...`,
  `subprocess.run(timeout=INSPECT_TIMEOUT)`): зависший/упавший экстрактор kill'ится
  гарантированно и не роняет бот, таймаут виден в логе. `YTDLP_ISOLATE_INSPECT=0`
  возвращает старый потоковый режим;
* `DROP_PENDING_UPDATES=1` по умолчанию + дедуп активной задачи по `(url, quality)` +
  игнор апдейтов старше времени старта процесса;
* отменённая задача больше не вычищает из `svc.jobs` задачу-преемника;
* `SystemExit`/`KeyboardInterrupt` из `to_thread` гасятся внутри `run_job`, а не пробрасываются
  в event loop;
* `SIGTERM` логируется («процесс останавливают извне») — сразу видно, что убил процесс
  хост, а не бот. Если процесс всё же подвис, включи `FAULTHANDLER_INTERVAL=60` на время
  отладки: в stderr пойдут стеки всех потоков (по умолчанию выключено, чтобы не сорить логи).

Новые строки лога: `нормализовал ссылку`, `разведка: subprocess старт/rc/ТАЙМАУТ`,
`дубль ссылки, пропускаю`, `пропускаю устаревший update`, `получен сигнал SIGTERM`.

## Стенд на 256 МБ ОЗУ

Замеры на Python 3.11 + aiogram 3.34 (RSS после импорта):

| Процесс | RSS |
|---|---|
| `import aiogram` | **163 МБ** |
| `import bot` (раньше, с top-level `yt_dlp`) | 177 МБ |
| `import bot` сейчас | **163 МБ** (yt-dlp грузится лениво) |
| дочерний `python -m yt_dlp -J` | 37–49 МБ, на реальном YouTube больше |
| `ffmpeg` при пережатии | ~100+ МБ |

То есть родитель + ребёнок + ffmpeg на 256 МБ не влезают — OOM-killer убивает контейнер
сразу после `разведка: subprocess старт`. Это не «большой файл», а сумма трёх процессов.

**`MEMORY_PROFILE=auto`** (по умолчанию) читает `cgroup memory.max` → `MemTotal` и при лимите
<384 МБ включает **LOW**:

* `MAX_PARALLEL=1`, очередь ≤8, `MAX_ORIGINAL_MB≤150`, `MAX_SLIDES≤10`, `MAX_IMAGE_MB` тот же;
* yt-dlp **не импортируется в родителе** (версия берётся из `importlib.metadata`), экономим ~13 МБ;
* дочерний `yt-dlp` получает жёсткий `ulimit -v 128 МБ` через shell (`preexec_fn` не используем —
  он небезопасен в многопоточном asyncio). При превышении падает ребёнок, а не бот;
* CLI разведки добавляет `--concurrent-fragments 1 --extractor-retries 0`;
* **пережатие ffmpeg и `bv+ba` merge отключены**: только прогрессивный формат, файлы >48 МБ
  уходят кнопкой «Открыть источник»; `ffprobe` в этом режиме не вызывается;
* `gallery-dl` и лишние коннекты отключены (`TCPConnector(limit=4)`, 2 потока на карусель).

Явные значения из `.env` в LOW **не могут превысить** потолки (иначе скопированный
`.env.example` с `MAX_PARALLEL=2` снова уронил бы стенд). `MEMORY_PROFILE=low` включает режим
принудительно, `normal` — запрещает. `YTDLP_MAX_AS_MB` переопределяет лимит ребёнка.

Проверка: `python bot.py --doctor` печатает `память: лимит=… · профиль=LOW · RSS=… ·
yt-dlp ulimit=…` и строку `⚠ LOW-MEMORY`, `/diag` добавляет `VmRSS`/`maxRSS`/число потоков.
В логе старта — `LOW-MEMORY (лимит N МБ): parallel=1, ffmpeg-пережатие отключено…`.

Если хостинг не отдаёт `/sys/fs/cgroup/memory.max`, `--doctor` честно пишет, что лимит взят
из `MemTotal` хоста (может быть 4 ГБ при реальных 256 МБ) — тогда задай
`MEMORY_PROFILE=low` в `.env` вручную.

> Честно: 163 МБ — это сам aiogram + pydantic + aiohttp. Меньше без смены фреймворка
> (прямой HTTP к Bot API) не сделать. На 128 МБ этот стек не влезет в принципе; на 256 МБ
> LOW оставляет ~90 МБ запаса. Если хост позволяет — 512 МБ и `MEMORY_PROFILE=normal`
> вернут пережатие и параллелизм.

## Ограничения платформы (не баги, а Bot API 10.4)

* По документам виджеты в проде — **только приватные чаты с ботом**, всегда `protect_content`,
  не форвардятся, не копируются; группы/инлайн/форварды — test server. **Фактически с
  13.11.2026 прод закрыт для обычных ботов целиком** — см. раздел выше.
* Старые клиенты (< layer 233) видят unsupported-медиа → бот ловит ошибку `sendWidget` и
  уходит в тихий фолбэк: одно текстовое сообщение + inline-клавиатура с теми же командами.
* HTML виджета **не редактируется после отправки** — только `chat_data`. Поэтому все фазы
  (`idle → queued → meta → down → encode → up → done → carousel → error`) рисует один HTML.
* Виджет ≤ 32 КБ raw / **≤ 4 КБ после zlib-9** (у нас 4563 / **1978** Б), `chat_data` ≤ 1 КБ,
  QuickJS без сети, только `data:`-картинки, системные шрифты, ≤2 `backdrop-filter`,
  максимум 600px, без внутреннего скролла.
* Bot API 10.5: `getMe()` теперь возвращает `BotFullInfo`; `callback_query_mode` по умолчанию
  `default` (иначе callback'и приходят с `inline_message_id` без `message`). Опционально
  `ENSURE_CALLBACK_MODE_DEFAULT=1` вызывает `setMySettings(callback_query_mode="default")`.

Подробности, точные сигнатуры методов, таблица лимитов и ссылки — в
[`docs/BOT_API_WIDGETS.md`](docs/BOT_API_WIDGETS.md).
